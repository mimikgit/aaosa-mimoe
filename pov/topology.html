AAOSA agent mesh on mimOE

On Node A, neuro-san runs a lab_assistant agent that calls the coordinator over MCP. The coordinator (on mimOE) negotiates with the network and device specialists over the AAOSA mesh, and every agent reaches an inference engine: the network specialist runs a model on its own machine, the device node borrows Node A's.

The outer panels are machines, not processes. Node A runs both a neuro-san server (the lab_assistant) and mimOE (the coordinator plus the shared model); Nodes B and C are mimOE nodes. Every node serves the same addon at the same path, /mimik-aaosa/agent/v1; a per-node ini file decides its role, so there is no separate coordinator build.

Moving dots show traffic direction. MCP and AAOSA are request and response, so they run both ways; inference calls flow one way, from an agent to its model. Node B keeps inference on its own machine, which is why its model is small and token-capped: a peer's whole reply must return inside mimOE's roughly 20 second outbound-read ceiling. Node C has no local model and calls Node A's shared one. The dotted line is optional: neuro-san's lab_assistant can reason on the local shared model instead of a cloud model.

Nothing here is wired by configuration. The coordinator does not hold a peer list: it asks its own node's mimOE mesh service who is nearby and which of them run the aaosa service. Add a fourth node and it joins the negotiation on the next inquiry; stop one and it leaves. Roles, not hardware: the validated reference lab used two laptops and a Raspberry Pi, but any two or three machines on one LAN work. See pov/RUNBOOK.md, appendix B.
